## 工作概述

升级后的 ChatGPT/Codex 将 CLI 从旧的 `Contents/Resources/codex` 移到 `Contents/Resources/codex-cli/bin/codex` wrapper 及其嵌套二进制路径，导致油表盘找不到可执行文件、无法启动 App Server 和读取额度。本 Work Item 只修复 CLI 路径兼容，不改变 App Server 协议、额度模型或 UI。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：兼容当前 ChatGPT/Codex CLI bundle 布局，并保留旧版安装布局。
- **验收标准**：新版 wrapper、嵌套 CLI 二进制和旧版 `Contents/Resources/codex` 均可定位；升级版 App Server 能完成 initialize 与 `account/rateLimits/read`；额度能继续进入现有菜单栏和悬浮面板流程。
- **实现证据**：`codex-fuel/Sources/CodexFuelGauge/CodexBinaryLocator.swift` 保留旧路径并增加新版 wrapper/嵌套二进制候选；定位函数支持注入 bundle URL、用户目录和文件系统。
- **验证证据**：7 项定位测试、17 项定位/协议/AppModel 测试通过；当前 CLI wrapper 的 initialize 与 `account/rateLimits/read` 探针返回额度字段；clean scratch release 构建、`package_app.sh` 和安装版 App Server 子进程 smoke 通过。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：不适用：未延期。

## 决策

### DEC-001 — 新旧 Codex CLI 路径兼容策略

- **状态**：RESOLVED
- **确认路径**：当前仓库实现、升级后的本机 ChatGPT.app bundle 和 App Server 探针。
- **决定**：保留旧版 `Contents/Resources/codex`，优先支持新版 `Contents/Resources/codex-cli/bin/codex` wrapper，并以 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex` 作为直接二进制 fallback。
- **原因**：wrapper 是新版 bundle 提供的稳定入口，直接二进制可覆盖 wrapper 缺失或布局不完整的环境。
- **取舍**：增加少量候选路径和测试注入点，不扫描任意目录，避免误启动其他同名可执行文件。
- **证据**：当前安装 ChatGPT.app 版本 `26.1013.40934`、CLI `0.163.0-alpha.10.2` 及实际 `account/rateLimits/read` 探针返回。

## Bug Fix 闭环

- **症状**：Codex 升级后油表盘额度区域无法获取额度，连接状态显示找不到 Codex 可执行文件；油表盘进程没有启动 App Server 子进程。
- **复现**：在当前 ChatGPT.app `26.1013.40934` 与 CLI `0.163.0-alpha.10.2` 环境运行油表盘；旧 `Contents/Resources/codex` 不存在，新 `Contents/Resources/codex-cli/bin/codex` 存在。
- **根因**：`CodexBinaryLocator` 只检查旧版 `Contents/Resources/codex` 路径，没有检查新版 `codex-cli` wrapper 或嵌套 CLI 路径。
- **失败机制**：定位返回 `nil`，`AppModel.connect()` 进入 `unavailable("未找到 Codex 可执行文件")` 并安排重试，因此 `CodexAppServerClient.start()` 从未执行。
- **修复**：增加新版 wrapper/嵌套二进制候选，保留旧路径，并通过注入 seam 覆盖路径优先级。
- **回归保护**：7 项旧版/新版定位测试、17 项 App Server 协议/AppModel/定位测试、当前 CLI 实际探针和 release 打包校验；安装版额度 UI 仍需用户回归。
