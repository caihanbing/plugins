## 工作概述

恢复油表悬浮面板的鼠标拖动能力。`FloatingPanelController` 曾只依赖 `isMovableByWindowBackground`，而 `GaugeRootView` 由铺满面板的 `ScrollView` 承载，没有可靠的显式窗口拖动入口。本次在顶部“CODEX FUEL / 额度仪表”标题区提供专用拖动句柄，正文继续由现有 `ScrollView` 承载。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：用户可从顶部标题区拖动油表面板，且窗口移动会保存新位置。
- **验收标准**：标题区拖动会改变窗口位置；`windowDidMove` 将新位置写入 `floatingPanelOrigin`。
- **实现证据**：`GaugeView.swift` 的 `PanelWindowDragHandle` 将 `DragGesture` 位移交给 `PanelDragCoordinator`；`FloatingPanelController` 显式允许窗口移动，原有 `windowDidMove` 持续保存 `floatingPanelOrigin`。
- **验证证据**：最终安装版长距离标题拖动将保存坐标从 `{1113, 356}` 精确更新到 `{1213, 256}`，证明连续位移按屏幕指针差移动；拖动后恢复到测试前的 `{1068, 389}`。`windowDidMove` 持久化路径和原有启动恢复逻辑未变。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：不适用：未延期。

### REQ-002 — 保持正文交互

- **需求**：拖动处理只占用顶部标题区；正文保留滚动行为，排行 Picker 仍可操作。
- **验收标准**：正文拖动不移动面板并可滚动内容；排行 Picker 可切换指标。
- **实现证据**：拖动句柄仅叠加在标题 HStack；外层 `ScrollView`、正文和 Picker 未添加拖动处理或禁用状态。
- **验证证据**：安装版点击 Picker 可从 CPU 切至内存并恢复 CPU；正文拖动没有改变保存的窗口坐标。自动化滚轮/正文拖动未观察到明确的滚动偏移，因此正文滚动仍待用户手动确认。
- **状态**：IMPLEMENTED
- **延期依据**：不适用：未延期。
- **后续工作**：用户回归确认正文可滚动后补录验证结果。

### REQ-003 — 重新打开后恢复位置

- **需求**：关闭并重新打开油表盘后恢复上次保存的面板位置。
- **验收标准**：重启应用后 `FloatingPanelController.restorePosition()` 从 `floatingPanelOrigin` 读取并设置窗口坐标。
- **实现证据**：`FloatingPanelController.restorePosition()` 在初始化时解析 `UserDefaults` 中的 `floatingPanelOrigin`，并调用 `panel.setFrameOrigin`；该逻辑未因本次变更修改。
- **验证证据**：本次最终安装版本已验证窗口坐标保存；关闭并重新打开该最终版本的 GUI 回归尚未完成。
- **状态**：IMPLEMENTED
- **延期依据**：不适用：未延期。
- **后续工作**：用户回归关闭并重新打开安装版，确认恢复坐标后补录结果。

## 决策

### DEC-001 — 使用顶部标题区作为面板拖动入口

- **状态**：RESOLVED
- **确认路径**：用户已选择仅在顶部标题区拖动。
- **决定**：仅标题区覆盖专用 SwiftUI `DragGesture`；每次更新读取 `NSEvent.mouseLocation` 的屏幕坐标增量并调用 `NSWindow.setFrameOrigin`，同时关闭 `isMovableByWindowBackground`。
- **原因**：安装版上 `NSWindow.performDrag(with:)` 和 `WindowDragGesture` 均未启动非激活 `NSPanel` 的移动；屏幕指针的逐事件增量避免窗口移动后局部坐标系随之变化。关闭背景拖动确保只有标题区能够发起移动。
- **取舍**：用户需从标题区开始拖动；换取正文滚动和控件行为不变。
- **证据**：`GaugeView.swift` 的标题行 overlay 和 `PanelWindowDragHandle`；`FloatingPanelController.swift` 的 `PanelDragCoordinator`、`NSEvent.mouseLocation`、`isMovableByWindowBackground = false` 和 `windowDidMove`。

## 实施记录

根因来自窗口没有可靠的显式拖动入口：无边框、非激活 `NSPanel` 虽启用 `isMovableByWindowBackground`，其内容由覆盖面板的 SwiftUI `ScrollView` 承载，标题区也没有窗口移动手势。安装版实测 `NSWindow.performDrag(with:)` 和 `WindowDragGesture` 未启动移动，因此改为仅覆盖标题行的 SwiftUI `DragGesture`，按 `NSEvent.mouseLocation` 的屏幕坐标增量调用 `setFrameOrigin`，并关闭任意背景拖动，避免标题区以外出现原生移动路径。正文 `ScrollView` 与 Picker 保持原状。

## Bug Fix 闭环

- **症状**：油表面板无法用鼠标拖动。
- **复现**：在已打开的面板上按住顶部标题行或空白背景拖动，面板位置不变；面板主体使用纵向 `ScrollView`。
- **根因**：仅依赖 `isMovableByWindowBackground`，但无边框、非激活 `NSPanel` 的 SwiftUI 内容没有可靠的显式拖动入口；标题区位于根 `ScrollView` 内容中。
- **失败机制**：安装版执行 `NSWindow.performDrag(with:)` 与 `WindowDragGesture` 时均未启动窗口移动；日志出现 `Window move completed without beginning`。手势事件需要显式转成窗口坐标更新。
- **修复**：在标题行增加专用 SwiftUI `DragGesture`，由 `PanelDragCoordinator` 按屏幕指针逐事件增量调用 `setFrameOrigin`；保留 `isMovable` 和 `windowDidMove` 持久化，关闭 `isMovableByWindowBackground`。
- **回归保护**：安装版已验证标题拖动会更新保存坐标、位置恢复和 Picker 操作；正文拖动不移动窗口。滚动位移和跨 Space 行为仍待用户手动回归，不把自动化中未观察到的滚动变化记作通过。
